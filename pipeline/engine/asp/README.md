# ASP engine (core)

The rule engine behind the "Clingo" option of the Gợi ý học phần page. Only the ASP
core lives here; the web feeds it through the adapter `pipeline/planner/solve_asp.py`
(input contract, output and differences with CP-SAT: `pipeline/planner/ASP-ADAPTER.md`).

Origin: `pipeline/engine/asp/core/*.lp` and `policy.lp` of the `research-pipeline`
branch (commit `84e41f1`). The Python pipeline and the illustrative JSON data of that
branch are intentionally not copied.

## Files and load order

```
core/encoding.lp   generic sets/maps and set constraints (no domain knowledge)
core/extension.lp  planning semantics (calendar, groups, prerequisites, loads, gaps,
                   offering, milestones, GPA, tuition, majors, tags, offering history)
policy.lp          the school's policy (hand-maintained on this branch)
<facts>            curriculum + student + scenario facts, generated by the adapter
core/translate.lp  student history -> engine vocabulary
core/optimize.lp   objectives (@8..@0) and #show
```

The adapter passes source text to clingo (not file paths): clingo on Windows cannot open
paths with non-ASCII characters (`ĐACN`).

## Changes compared with research-pipeline (20/11/2026)

| Where | Change |
|---|---|
| `extension.lp` §9 | Per-term bounds `sem_max(I,M)` / `sem_min(I,M)` narrow the policy `load_bound`; if a student's maximum is below the minimum, the minimum follows it down |
| `extension.lp` §9, `optimize.lp` | The core-term contiguity rule is soft: an empty core term before the last used one is `gap(J)`, minimised at `@8` and shown; `skip(J)` keeps term J empty without a gap. Previously a hard constraint (and empty terms right after the current term were not detected) |
| `extension.lp` §13 | Tuition is optional: without `fee_rule/6` there is no fee, no cost objective, no "unbilled term" constraint |
| `extension.lp` §19, `optimize.lp` | `popularity/2` replaced by offering history `offer_hist(E,P,N)` / `offer_seen(P,M)` and `offer_miss/3` (percent of observed terms of part P in which E did not open), minimised at `@5` |
| `extension.lp` §11, `translate.lp` | Raw scores `raw_score(X,V)` (score_10, x100): the letter is derived from the score (`grade_min_score/3`, the score wins over a given letter) and decides passed/failed, earned credit and the gpa_4 points; the score itself is the score_10 GPA value. The separate score-only status/earned/credited rules are gone: every attempt goes through its letter |
| `translate.lp`, `extension.lp` §11 | Retake cap on both scales: `capped(X)` marks a retake whose letter `retake_grade_cap/1` lowered; its score_10 GPA value is then the capped letter's midpoint (B → 7.5), not the raw score |
| `optimize.lp` | Objective levels renumbered: `@8 gaps, @7 last_semester, @6 retakes, @5 offering_history, @4 cost, @3 typical_term, @2 level_order, @1 balance, @0 taste` |
| `policy.lp` | `grade_min_score(score_10, G, Lo)` added (score → letter, `min_score` of `grading_policy.json` in research-pipeline); `map(l/u, total_degree, 128)` and `graduation_requirement(min_total_credits, 128)` removed (curriculum-specific, emitted by the adapter); header updated (no generator on this branch) |

`retake_grade_cap(b)` in `policy.lp` is a rule of thumb, not a verified regulation. The web
stores one attempt per course, so the cap has no effect on the site yet (tested in
`pipeline/planner/tests/test_solve_asp.py::test_retake_cap_applies_to_score_scale`).
